## 1. BasicTokenizer의 한계 — 단어 경계 무시

BasicTokenizer는 텍스트를 하나의 긴 바이트 스트림으로 취급합니다.
단어와 단어 사이의 경계를 전혀 고려하지 않습니다.

### 구체적인 문제 예시

다음 텍스트로 BPE를 학습한다고 가정합니다.

```
"dog! dog! dog! new new new"
```

BasicTokenizer는 이것을 하나의 연속된 바이트 스트림으로 봅니다.

```
d o g !   d o g !   d o g !   n e w   n e w   n e w
```

빈도를 세면:

```
'd'+'o' → 3회
'o'+'g' → 3회
'g'+'!' → 3회
'!'+ ' ' → 3회
' '+'d' → 2회  (마지막 'new' 이전에는 'd'가 옴)
' '+'n' → 3회
'n'+'e' → 3회
'e'+'w' → 3회
```

여러 번의 병합을 거치면 결국 다음과 같은 토큰이 생길 수 있습니다.

```
'g! n'  ← '!'과 'n' 사이의 공백을 포함해서 병합됨!
```

이 토큰은 의미가 없습니다. 구두점 `!` 다음에 오는 공백과 다음 단어의 첫 글자가
하나의 토큰이 된 것입니다. **단어와 단어 사이의 경계를 넘어 병합이 일어났습니다.**

### 또 다른 사례 — "New York" 문제

```
학습 텍스트: "New York is a city. New York is big."

BasicTokenizer 병합 결과 (일부):
  'k'+'space' → 'k '  ← "Yor[k ]is" 패턴
  'k '+'i'   → 'k i'  ← "Yor[k i]s" 패턴

  → 단어 경계를 넘은 'k i'가 하나의 토큰이 됨!
```

이것은 두 가지 문제를 일으킵니다.

1. 의미 없는 토큰이 어휘집을 차지합니다. (vocab 낭비)
2. 인코딩이 문맥에 따라 달라집니다. ("York" 뒤에 무엇이 오느냐에 따라 토큰이 달라짐)

## 2. RegexTokenizer의 해결책 — 먼저 잘라서 나눈다

RegexTokenizer의 핵심 아이디어는 이것입니다.

> **BPE를 적용하기 전에, 먼저 정규식으로 텍스트를 의미 단위로 분리한다.**
> **각 조각 안에서만 BPE 병합을 허용하고, 조각 사이를 넘는 병합은 금지한다.**

### 작동 방식

```
원본 텍스트: "Hello, world! New York."

1단계 — 정규식으로 먼저 분리:
  ["Hello", ",", " world", "!", " New", " York", "."]
   ↑글자    ↑구두점  ↑공백+글자  ↑구두점  ...

2단계 — 각 조각 안에서만 BPE 병합:
  "Hello"  → 내부에서만 병합 허용
  ","      → 단독으로 처리
  " world" → 내부에서만 병합 허용
  ...

결과: 단어 경계를 넘는 병합이 구조적으로 불가능!
```

이렇게 하면 `','`와 `' w'`가 합쳐져 `', w'` 같은 무의미한 토큰이 생기지 않습니다.

## 3. GPT-4 tiktoken의 정규식 패턴

GPT-4(tiktoken)가 실제로 사용하는 정규식 패턴은 다음과 같습니다.

```python
GPT4_SPLIT_PATTERN = (
    r"""'(?i:[sdmt]|ll|ve|re)|"""    # 영어 축약형 처리
    r"""[^\r\n\p{L}\p{N}]?+\p{L}+|""" # 글자(Letter) 카테고리
    r"""\p{N}{1,3}|"""               # 숫자 (최대 3자리씩)
    r""" ?[^\s\p{L}\p{N}]++[\r\n]*|""" # 구두점/특수문자
    r"""\s*[\r\n]|"""                # 줄바꿈
    r"""\s+(?!\S)|"""                # 공백 (마지막 단어 앞 제외)
    r"""\s+"""                       # 나머지 공백
)
```

이 패턴을 처음 보면 복잡해 보입니다. 하나씩 이해해 봅시다.

### 패턴 1 — 영어 축약형 처리

```
'(?i:[sdmt]|ll|ve|re)
```

예시:

```
"don't"  → ["don", "'t"]   ← 't 를 별도로 분리
"I'll"   → ["I", "'ll"]    ← 'll 를 별도로 분리
"they've"→ ["they", "'ve"] ← 've 를 별도로 분리
"he's"   → ["he", "'s"]    ← 's 를 별도로 분리
```

`don't`를 하나로 묶으면 `don`과 `do n't`가 다른 토큰이 되어버립니다.
축약형을 분리하면 `don`이라는 어근이 항상 같은 토큰으로 처리됩니다.

### 패턴 2 — 글자(Letter) 카테고리

```
[^\r\n\p{L}\p{N}]?+\p{L}+
```

`\p{L}`은 모든 언어의 글자를 의미합니다 (영어, 한국어, 일본어, 아랍어 등).

예시:

```
"hello"   → ["hello"]           ← 영어 단어
" world"  → [" world"]          ← 앞 공백 포함
"안녕"    → ["안녕"]            ← 한국어
" 안녕"   → [" 안녕"]           ← 앞 공백 포함 한국어
```

### 패턴 3 — 숫자 (최대 3자리씩)

```
\p{N}{1,3}
```

예시:

```
"123"      → ["123"]              ← 3자리 숫자 → 하나의 토큰
"12345"    → ["123", "45"]        ← 3자리씩 분리
"3.14"     → ["3", ".", "14"]     ← 소수점으로 분리
```

왜 3자리씩 제한하는가? 숫자가 너무 많이 묶이면 "100", "200", "300" 등이 각각
다른 토큰이 되어 어휘집을 낭비합니다. 짧게 제한하면 숫자 토큰의 재사용성이 높아집니다.

### 패턴 4 — 구두점과 특수문자

```
 ?[^\s\p{L}\p{N}]++[\r\n]*
```

예시:

```
"!"   → ["!"]
", "  → [","]  + [" "]  (공백은 다음 패턴)
"..."  → ["..."]
```

글자도 숫자도 공백도 아닌 모든 것(구두점, 특수문자)을 분리합니다.

### 전체 분리 결과 예시

```
원본:  "Hello, world! I'm learning NLP in 2024."

분리 결과:
  ["Hello", ",", " world", "!", " I", "'m", " learning", " NLP", " in", " 2024", "."]
```

이제 각 조각 안에서만 BPE가 적용됩니다.
`","` 와 `" world"` 사이를 넘는 병합은 절대 일어나지 않습니다.

## 4. GPT-2 vs GPT-4의 정규식 차이

GPT-2가 사용한 구형 패턴과 GPT-4의 패턴을 비교해 봅시다.

### GPT-2 패턴 (구형)

```python
GPT2_SPLIT_PATTERN = (
    r"""'s|'t|'re|'ve|'m|'ll|'d|"""  # 영어 축약형 (소문자만)
    r"""[^\S\r\n]?[a-zA-Z]+|"""       # 영어 글자만 (다국어 미지원!)
    r"""\d+|"""                        # 숫자 (길이 제한 없음)
    r"""[^\s\w]"""                     # 그 외
)
```

문제점:

```
영어 전용:  "[a-zA-Z]+"는 한국어, 일본어 등을 인식하지 못합니다.
대소문자:  "'s"는 인식하지만 "'S"는 인식 못 합니다.
숫자:      길이 제한이 없어 "1000000"이 하나의 토큰이 될 수 있습니다.
```

### GPT-4 패턴 (신형)

```
`\p{L}` 사용: 모든 언어의 글자를 포함 (유니코드 Letter 카테고리)
`(?i:...)` 사용: 대소문자 구분 없이 축약형 처리
숫자를 1~3자리로 제한: 어휘집 낭비 방지
```

GPT-4가 GPT-2보다 한국어, 중국어 등을 훨씬 효율적으로 처리하는 이유 중 하나입니다.

## 5. 왜 RegexTokenizer가 더 나은가?

BasicTokenizer와 RegexTokenizer를 직접 비교해 봅시다.

```
학습 텍스트: "dog! dog! dog! cat cat cat"

BasicTokenizer 학습 후 토큰 예시:
  '!'+ ' '  → 합쳐질 수 있음 (구두점+공백이 하나의 토큰)
  ' '+'c'   → 합쳐질 수 있음 (공백+글자가 하나의 토큰)
  → 단어 경계를 넘는 의미 없는 토큰들이 생성됨

RegexTokenizer 학습 후 토큰 예시:
  정규식 분리 후: ["dog", "!", " dog", "!", " dog", "!", " cat", " cat", " cat"]
  각 조각 안에서만 병합:
  ' '+'d' → ' d'  (공백과 'd'만, 항상 단어 시작을 나타냄)
  'd'+'o' → 'do'
  'do'+'g' → 'dog'
  → 의미 있는 토큰만 생성됨
```

RegexTokenizer는 언어 구조를 반영한 더 깔끔한 어휘집을 만듭니다.

## 정리

| 개념 | BasicTokenizer | RegexTokenizer |
|---|---|---|
| 병합 범위 | 텍스트 전체 | 정규식으로 분리된 조각 안에서만 |
| 단어 경계 인식 | 없음 | 있음 |
| 다국어 지원 | 부분적 | 완전 지원 (GPT-4 패턴) |
| 어휘집 품질 | 의미 없는 토큰 가능 | 의미 있는 토큰 위주 |
| 실무 사용 | 없음 | GPT-2, GPT-4 (tiktoken) |

## 핵심 요약

BasicTokenizer는 BPE의 핵심 원리를 가르치기에 좋습니다.
하지만 실무에서는 **정규식으로 단어 경계를 먼저 분리**한 뒤 BPE를 적용하는
RegexTokenizer 방식이 사용됩니다.

GPT-4 tiktoken의 정규식 패턴은 다음 범주 사이의 경계를 넘는 병합을 방지합니다.

```
글자(Letter) | 숫자(Number) | 구두점 | 공백 | 줄바꿈
```

이 원리를 이해하면 GPT-2, GPT-4, LLaMA 등 모든 현대 언어 모델의
토크나이저가 어떻게 작동하는지 완전히 이해한 것입니다.
