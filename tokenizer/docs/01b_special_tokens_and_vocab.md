# 01b. Special Token과 어휘집 관리

## 목표

이 문서를 읽고 나면 다음 질문에 답할 수 있게 됩니다.

- [PAD], [UNK], [BOS], [EOS]는 각각 어떤 역할을 하는가?
- 배치 처리에서 PAD가 없으면 어떤 문제가 생기는가?
- encode_batch의 결과가 실제로 어떻게 생겼는가?
- 어휘집을 JSON으로 저장하면 어떤 모습인가?

---

## 1. Special Token이란?

토크나이저의 어휘집에는 실제 글자나 단어 외에도, **특별한 목적을 위해 만들어진 토큰**이 포함됩니다. 이것을 특수 토큰(Special Token)이라고 합니다.

특수 토큰은 글자가 아닙니다. 모델에게 "지금 특별한 상황"임을 알려주는 신호입니다.

우리가 사용하는 네 가지 특수 토큰을 하나씩 살펴봅시다.

---

## 2. [PAD] — 채우기 토큰 (Padding Token, ID = 0)

### 왜 필요한가?

AI 모델은 여러 문장을 한꺼번에 처리할 때 훨씬 빠릅니다. 이것을 **배치 처리(Batch Processing)** 라고 합니다.

그런데 문장마다 길이가 다르면 문제가 생깁니다. 컴퓨터의 행렬(Matrix) 연산은 모든 행의 열 수가 같아야 합니다. 들쭉날쭉한 길이는 허용되지 않습니다.

### PAD 없이 배치 처리하면 어떤 문제가 생기는가?

```
문장 A: [BOS] h e l l o [EOS]          ← 길이 7
문장 B: [BOS] h i [EOS]                ← 길이 4
문장 C: [BOS] w o r l d [EOS]          ← 길이 7

→ B의 길이가 달라서 하나의 직사각형 행렬로 묶을 수 없음!

[ 7, 5, 4, 6, 6, 7, 3 ]   ← 문장 A (7개)
[ 2, 5, 8, 3 ]             ← 문장 B (4개)  ← 길이가 달라 에러!
[ 2, 9, 7, 10, 6, 4, 3 ]  ← 문장 C (7개)
```

### PAD로 해결하기

짧은 문장의 빈 자리를 [PAD] 토큰(ID = 0)으로 채웁니다.

```
문장 A: [BOS] h  e  l  l  o  [EOS]                ← 길이 7
문장 B: [BOS] h  i  [EOS] [PAD] [PAD] [PAD]       ← 길이 7로 맞춤
문장 C: [BOS] w  o  r  l  d  [EOS]                ← 길이 7

ID로 표현하면:
[ 2, 5, 4, 6, 6, 7, 3 ]   ← 문장 A
[ 2, 5, 8, 3, 0, 0, 0 ]   ← 문장 B (뒤 세 자리가 PAD = 0)
[ 2, 9, 7, 10, 6, 4, 3 ]  ← 문장 C

→ 모두 길이 7. 하나의 행렬로 묶을 수 있음!
```

모델은 [PAD] 위치를 "없는 것"으로 취급하도록 학습됩니다. (Attention Mask라는 기법으로 처리합니다.)

## 3. [UNK] — 미지 토큰 (Unknown Token, ID = 1)

### 왜 필요한가?

어휘집에는 학습 데이터에 등장한 글자만 등록됩니다. 나중에 실제로 사용할 때 학습에 없던 글자가 등장하면 어떻게 해야 할까요?

가장 단순한 방법은 에러를 내는 것입니다. 하지만 실무에서는 이것이 허용되지 않습니다. 사용자가 어떤 글자를 입력할지 미리 알 수 없기 때문입니다.

대신, 어휘집에 없는 글자는 조용히 [UNK]로 대체합니다.

```
어휘집: { '[PAD]', '[UNK]', '[BOS]', '[EOS]', 'h', 'e', 'l', 'o' }

입력: "hello!"   ← '!'는 어휘집에 없음

처리 결과:
  'h' → ID 5
  'e' → ID 4
  'l' → ID 6
  'l' → ID 6
  'o' → ID 7
  '!' → [UNK] (ID 1)   ← 에러 대신 UNK로 대체

인코딩: [5, 4, 6, 6, 7, 1]
```

### UNK의 한계

[UNK]로 대체하면 프로그램이 멈추지는 않지만, 그 글자의 의미는 사라집니다. 많은 글자가 [UNK]로 대체되면 모델이 제대로 된 처리를 할 수 없게 됩니다.

이것이 바로 BPE가 등장한 이유 중 하나입니다. BPE는 UTF-8 바이트 단위로 시작하므로 어떤 글자든 표현할 수 있어, [UNK]가 사실상 필요 없습니다.

---

## 4. [BOS] — 문장 시작 토큰 (Beginning Of Sequence, ID = 2)

### 왜 필요한가?

GPT 같은 언어 모델은 이전 토큰을 보고 다음 토큰을 예측하는 방식으로 작동합니다. 맨 처음 토큰을 예측할 때는 "이전 토큰"이 없습니다.

[BOS]가 그 첫 번째 토큰 역할을 합니다. 모델은 [BOS]를 받으면 "지금부터 새 문장을 생성해야 한다"는 신호로 받아들입니다.

```
모델 입력:
  [BOS]
  ↓
  모델이 첫 번째 글자를 예측: 'h'
  ↓
  모델이 두 번째 글자를 예측: 'e'
  ↓
  ...
  ↓
  모델이 [EOS]를 예측하면 멈춤
```

---

## 5. [EOS] — 문장 끝 토큰 (End Of Sequence, ID = 3)

### 왜 필요한가?

모델이 문장을 생성할 때, 어디서 멈춰야 할지를 알아야 합니다. [EOS]가 없으면 모델은 영원히 토큰을 생성하려 합니다.

학습 데이터의 모든 문장 끝에 [EOS]를 붙여두면, 모델은 "문장 끝에는 [EOS]가 온다"는 패턴을 학습합니다. 이후 추론(생성) 단계에서 모델이 [EOS]를 출력하면 생성을 멈춥니다.

## 6. encode_batch 결과 예시

다음 코드를 실행했을 때의 결과를 단계별로 살펴봅시다.

```python
tokenizer = CharTokenizer()
tokenizer.train("hello world hi")

texts = ["hello", "hi", "world"]
result = tokenizer.encode_batch(
    texts,
    add_special_tokens=True,
    pad_to_max_length=True,
)
```

### 어휘집 (학습 후)

```
[PAD] → 0
[UNK] → 1
[BOS] → 2
[EOS] → 3
' '   → 4   (공백)
'd'   → 5
'e'   → 6
'h'   → 7
'i'   → 8
'l'   → 9
'o'   → 10
'r'   → 11
'w'   → 12
```

### 각 문장의 인코딩 (add_special_tokens=True 적용 후, PAD 전)

```
"hello" → [BOS] h  e  l  l  o  [EOS]
         → [2,   7, 6, 9, 9, 10, 3]        길이: 7

"hi"    → [BOS] h  i  [EOS]
         → [2,   7, 8, 3]                  길이: 4

"world" → [BOS] w   o  r  l  d  [EOS]
         → [2,   12, 10, 11, 9, 5, 3]      길이: 7
```

### PAD 적용 후 (pad_to_max_length=True, 최대 길이 = 7)

```
"hello" → [2,  7,  6,  9,  9, 10,  3]        ← PAD 불필요
"hi"    → [2,  7,  8,  3,  0,  0,  0]        ← 뒤에 [PAD] 3개 추가
"world" → [2, 12, 10, 11,  9,  5,  3]        ← PAD 불필요
```

시각적으로 보면:

```
         위치:  0    1    2    3    4    5    6
문장 A:        [BOS] h    e    l    l    o   [EOS]
문장 B:        [BOS] h    i   [EOS][PAD][PAD][PAD]
문장 C:        [BOS] w    o    r    l    d   [EOS]
```

이제 세 문장이 모두 길이 7인 직사각형 행렬이 되었습니다. 모델에 한꺼번에 넣을 수 있습니다.

## 7. 어휘집을 JSON으로 저장하면 어떻게 생겼는가?

`tokenizer.save("tokenizer.json")`을 실행하면 다음과 같은 파일이 생성됩니다.

```json
{
  "vocab_size": 13,
  "char_to_id": {
    "[PAD]": 0,
    "[UNK]": 1,
    "[BOS]": 2,
    "[EOS]": 3,
    " ": 4,
    "d": 5,
    "e": 6,
    "h": 7,
    "i": 8,
    "l": 9,
    "o": 10,
    "r": 11,
    "w": 12
  },
  "special_tokens": [
    "[PAD]",
    "[UNK]",
    "[BOS]",
    "[EOS]"
  ]
}
```

이 파일의 구조를 보면 알 수 있는 것들:

- 특수 토큰이 항상 맨 위에 0번부터 시작합니다.
- 일반 글자는 알파벳 정렬 순서로 4번부터 시작합니다.
- `special_tokens` 항목은 어떤 토큰이 특수 토큰인지 명시합니다.

이 파일만 있으면 언제든지 `tokenizer.load("tokenizer.json")`으로 동일한 어휘집을 복원할 수 있습니다.

## 8. 저장된 어휘집을 반드시 써야 하는 이유

이것은 실무에서 가장 자주 발생하는 실수 중 하나입니다. 예시로 이해해 봅시다.

```
상황: 모델을 월요일에 학습하고, 수요일에 서비스를 배포합니다.

월요일 (학습할 때):
  어휘집: 'h' → 7, 'e' → 6, 'l' → 9, 'o' → 10
  모델은 ID 7을 보면 'h'라고 인식하도록 학습됨

수요일 (배포할 때, 어휘집을 새로 만들면):
  새 어휘집: 'e' → 4, 'h' → 5, 'l' → 6, 'o' → 7  ← 순서가 달라짐!
  "hello"를 인코딩하면 [5, 4, 6, 6, 7]
  모델은 ID 7을 'o'가 아니라 'h'라고 알고 있음 → 완전히 틀린 답!
```

이런 사고를 방지하기 위해 학습이 끝나면 항상 어휘집을 저장하고, 배포할 때는 저장된 파일을 불러옵니다.

## 정리

| 특수 토큰 | ID | 역할 |
|---|---|---|
| [PAD] | 0 | 배치 처리 시 짧은 문장의 빈 자리 채우기 |
| [UNK] | 1 | 어휘집에 없는 글자를 에러 없이 처리 |
| [BOS] | 2 | 모델에게 문장 시작 신호 전달 |
| [EOS] | 3 | 모델에게 문장 끝 신호 전달, 생성 멈춤 |

| 기능 | 메서드 | 설명 |
|---|---|---|
| 단일 인코딩 | `encode(text, add_special_tokens=True)` | 문장 하나를 ID 목록으로 변환 |
| 배치 인코딩 | `encode_batch(texts, pad_to_max_length=True)` | 여러 문장을 동일 길이로 변환 |
| 디코딩 | `decode(ids, skip_special_tokens=True)` | ID 목록을 문장으로 복원 |
| 저장 | `save(path)` | 어휘집을 JSON 파일로 저장 |
| 불러오기 | `load(path)` | JSON 파일에서 어휘집 복원 |
