## Q1. 단어 단위 토크나이저는 어떻게 문장을 쪼개는가? ⭐

<details>
<summary>▶ 답</summary>

**공백(whitespace)을 기준**으로 문장을 분리한다.

```python
"I love AI".split()  →  ['I', 'love', 'AI']
```

각 단어가 하나의 토큰이 되고, 어휘집에 단어 → ID 대응을 저장한다.

```
어휘집: {'I': 4, 'love': 5, 'AI': 6}
인코딩: [BOS] I love AI [EOS]  →  [2, 4, 5, 6, 3]
```

</details>

---

## Q2. 단어 단위가 글자 단위보다 나은 점은? ⭐

<details>
<summary>▶ 답</summary>

**시퀀스 길이가 짧아지고, 의미 단위로 처리할 수 있다.**

```
"I love machine learning"

글자 단위: I, ' ', l, o, v, e, ' ', m, a, c, h, i, n, e, ...  → 24개 토큰
단어 단위: I, love, machine, learning                          → 4개 토큰
```

- 토큰이 적을수록 모델의 연산량·메모리 감소
- "machine", "learning" 같은 의미 있는 단위로 AI가 언어를 학습할 수 있음

</details>

---

## Q3. OOV(Out Of Vocabulary) 문제란 무엇인가? ⭐

<details>
<summary>▶ 답</summary>

**학습(train) 때 보지 못한 단어가 인코딩 시 등장하는 상황.**

```
학습 텍스트: "I love machine learning"
→ 어휘집: {I, love, machine, learning}

인코딩 대상: "I love ChatGPT"
→ 'ChatGPT'가 어휘집에 없음 → OOV 발생!
→ [UNK]으로 대체: "I love [UNK]"
```

원래 단어가 무엇이었는지 **복원 불가능**하며, 모델은 의미를 전혀 알 수 없다.

</details>

---

## Q4. 단어 단위에서 OOV가 특히 심각한 이유는? ⭐⭐

<details>
<summary>▶ 답</summary>

세 가지 이유가 겹친다.

**1. 고유명사·신조어의 폭발적 증가**  
"ChatGPT", "메타버스", "NFT" — 학습 데이터 이후에 생긴 단어는 영구 OOV.

**2. 어휘집을 아무리 키워도 완전히 막을 수 없음**  
영어 단어 약 17만 개를 모두 등록해도 오타, 도메인 전문 용어, 외래어에서 OOV 발생.

**3. 글자 단위와 달리 우회가 없음**  
글자 단위는 알파벳 26자만 학습하면 사실상 OOV 없음.  
단어 단위는 "처음 보는 단어 = 무조건 UNK"로 정보 손실이 확정됨.

</details>

---

## Q5. 한국어에서 단어 단위 토크나이저가 특히 어려운 이유는? ⭐⭐

<details>
<summary>▶ 답</summary>

한국어는 **교착어(agglutinative language)** 라서, 하나의 어근에 수많은 어미·조사가 붙어 변형이 일어난다.

```
"가다" 하나만 봐도:
가다, 가고, 가서, 가면, 가니, 가지, 갔다, 가겠다,
가더라, 가는데, 갈수록, 가다가, 가려고 ...
```

영어 단어 수 ≈ 17만 개  
한국어 활용형 포함 ≈ 수백만 개 이상

→ 공백 기준 분리만으로는 형태소 변형을 처리할 수 없음  
→ vocab_size가 감당 불가능한 수준으로 폭발

</details>

---

## Q6. vocab_size 폭발 문제가 모델에 미치는 영향은? ⭐⭐

<details>
<summary>▶ 답</summary>

vocab_size는 모델의 **임베딩 행렬 크기**를 직접 결정한다.

```
임베딩 행렬 = vocab_size × embedding_dim

GPT-2 수준 (embedding_dim=768) 기준:
- 단어 단위 (vocab=170,000): 170,000 × 768 = 약 1.3억 파라미터 (임베딩만)
- BPE (vocab=50,257):         50,257 × 768 = 약 3,860만 파라미터 (임베딩만)
```

vocab이 3배 이상 커지면 임베딩 파라미터도 3배 증가 → 메모리, 학습 속도 모두 악화.  
또한 희귀 단어는 학습 데이터에 거의 등장하지 않아 임베딩이 제대로 학습되지 않는다.

</details>

---

## Q7. UNK 토큰으로 OOV를 처리할 때의 근본적인 한계는? ⭐⭐

<details>
<summary>▶ 답</summary>

**정보가 영구적으로 손실된다.**

```
"I love transformer architecture"
→ "I love [UNK] [UNK]"
```

- 모델은 [UNK]가 무슨 단어인지 알 수 없다
- [UNK]가 두 개면 어떤 단어가 각각 어디에 해당하는지도 알 수 없다
- 디코딩 시 원본 복원 불가능

UNK는 **임시방편**이며, 근본 해결책은 OOV 자체가 발생하지 않는 방식을 설계하는 것.  
→ BPE는 256 바이트로 시작해 OOV를 원천 차단한다.

</details>

## Q8. 글자 단위 vs 단어 단위를 비교 정리하라. ⭐⭐

<details>
<summary>▶ 답</summary>

| 항목 | 글자 단위 | 단어 단위 |
|---|---|---|
| 쪼개는 단위 | 글자 1개 | 공백으로 분리된 단어 |
| vocab_size | 매우 작음 (~100, 영어) | 매우 큼 (수십만~수백만) |
| 시퀀스 길이 | 매우 김 | 짧음 |
| OOV | 거의 없음 | 매우 빈번 |
| 의미 보존 | 낮음 | 높음 |
| 한국어 처리 | 가능하지만 시퀀스 극도로 길어짐 | 형태소 변형으로 사실상 불가 |
| 실무 사용 여부 | 거의 안 씀 | 거의 안 씀 |

→ 두 방식 모두 실무에서 단독으로 쓰기 어렵다. 이것이 **BPE 등장의 배경**이다.

</details>

## Q9. 왜 BPE가 등장했는가? 글자·단어 방식의 어떤 문제를 해결하는가? ⭐⭐⭐

<details>
<summary>▶ 답</summary>

**글자 단위의 단점**: 시퀀스가 너무 길고, 의미 단위를 잃음  
**단어 단위의 단점**: OOV 빈번, vocab_size 폭발

BPE는 두 방식의 절충점을 찾는다.

- **바이트(256개)에서 시작** → OOV 원천 차단 (글자 단위의 장점)
- **자주 붙어 나오는 조각을 하나로 합침** → 자주 쓰는 단어는 1개 토큰, 희귀 단어는 서브워드로 쪼갬 (단어 단위의 장점)

결과:
```
"tokenizer"  →  ['token', 'izer']   (서브워드)
"ChatGPT"    →  ['Chat', 'G', 'PT'] (OOV 없이 처리)
```

vocab_size를 ~50,000으로 제어하면서 대부분의 언어를 OOV 없이 처리할 수 있다.

</details>

| 개념 | 한 줄 정의 |
|---|---|
| 단어 단위 토크나이저 | 공백 기준으로 단어를 쪼개 숫자 ID로 변환 |
| OOV | 어휘집에 없는 단어가 등장하는 상황 |

| BPE 등장 배경 | 글자(OOV 없음 + 긴 시퀀스)와 단어(짧은 시퀀스 + OOV)의 절충 |
