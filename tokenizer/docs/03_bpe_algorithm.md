## 1. BPE의 핵심 직관

BPE를 한 문장으로 요약하면 이것입니다.

> **"자주 붙어 나오는 것은 하나로 묶자."**

이 직관은 일상에서도 볼 수 있습니다.

우리가 처음 외국어를 배울 때, 단어를 한 글자씩 외웁니다.
하지만 익숙해지면 자주 나오는 패턴을 통째로 인식합니다.

```
초보자: "d-i-s-a-p-p-e-a-r" (글자 9개를 따로 처리)
숙련자: "dis-appear"  (자주 나오는 접두사 'dis-'를 하나로 인식)
```

BPE도 동일합니다. 처음에는 모든 것을 글자(바이트)로 봅니다.
그러다 "이 두 글자는 항상 붙어 나오는구나"를 발견하면, 그 둘을 하나로 묶습니다.
이것을 반복하면 자연스럽게 의미 있는 단위(단어, 접두사, 접미사)가 형성됩니다.

## 2. 단계별 시각적 예시

아주 작은 텍스트로 BPE가 어떻게 작동하는지 손으로 따라가 봅시다.

### 학습 텍스트

```
"helloworld hellohello worldhello"
```

### 초기 상태 — 모든 것을 글자로 쪼갭니다

```
h e l l o w o r l d   h e l l o h e l l o   w o r l d h e l l o
```

ID로 표현하면 (각 글자의 ASCII 코드):

```
104 101 108 108 111 119 111 114 108 100 32
104 101 108 108 111 104 101 108 108 111 32
119 111 114 108 100 104 101 108 108 111
```

`h`=104, `e`=101, `l`=108, `o`=111, `w`=119, `r`=114, `d`=100, ` `=32

### 1번째 병합 — 가장 자주 나오는 쌍을 찾습니다

각 인접 쌍의 등장 횟수를 셉니다.

```
(104, 101) = h+e → 4회   ← 가장 많음!
(101, 108) = e+l → 4회   ← 동점
(108, 108) = l+l → 4회   ← 동점
(108, 111) = l+o → 4회   ← 동점
...
```

동점이면 어떤 쌍이든 선택할 수 있습니다. 여기서는 `(108, 108)` 즉 `l+l`을 선택합니다.

```
병합 규칙 1: (108, 108) → 256  ('l' + 'l' = 'll')

적용 전: h e l l o w o r l d
적용 후: h e [256] o w o r [256] d
                ↑               ↑
             'll' 토큰        'l' 홀로 남은 'l'은? → r+l+d 사이의 l은 ll이 아님
```

모든 `l l` 자리가 `256`번 토큰으로 교체됩니다.

```
적용 후 ID 목록:
104 101 256 111 119 111 114 256 100 32
104 101 256 111 104 101 256 111 32
119 111 114 256 100 104 101 256 111
```

### 2번째 병합 — 다시 가장 자주 나오는 쌍을 찾습니다

```
이제 목록에서 자주 나오는 쌍:
(101, 256) = e + 'll' → 4회   ← 'ell' 패턴
(104, 101) = h + e   → 4회
...
```

이번에는 `(104, 101)` 즉 `h+e`를 선택합니다.

```
병합 규칙 2: (104, 101) → 257  ('h' + 'e' = 'he')

적용 후:
257 256 111 119 111 114 256 100 32
257 256 111 257 256 111 32
119 111 114 256 100 257 256 111
```

### 3번째 병합

```
현재 자주 나오는 쌍:
(257, 256) = 'he' + 'll' → 4회   ← 가장 많음!
```

```
병합 규칙 3: (257, 256) → 258  ('he' + 'll' = 'hell')

적용 후:
258 111 119 111 114 256 100 32
258 111 258 111 32
119 111 114 256 100 258 111
```

### 4번째 병합

```
현재 자주 나오는 쌍:
(258, 111) = 'hell' + 'o' → 4회  ← 'hello' 패턴!
```

```
병합 규칙 4: (258, 111) → 259  ('hell' + 'o' = 'hello')

적용 후:
259 119 111 114 256 100 32
259 259 32
119 111 114 256 100 259
```

이제 'hello'가 단일 토큰(ID=259)이 되었습니다!

### 병합 과정 요약

```
시작:    h e l l o w o r l d [space] h e l l o h e l l o ...
         (많은 글자 토큰)

1회 병합: l+l → 'll'(256)
         h e [ll] o w o r [ll] d [space] h e [ll] o ...

2회 병합: h+e → 'he'(257)
         [he] [ll] o w o r [ll] d [space] [he] [ll] o ...

3회 병합: 'he'+'ll' → 'hell'(258)
         [hell] o w o r [ll] d [space] [hell] o ...

4회 병합: 'hell'+'o' → 'hello'(259)
         [hello] w o r [ll] d [space] [hello] [hello] ...
```

자주 등장하는 'hello'가 자연스럽게 하나의 토큰이 되었습니다.
사람이 알려주지 않아도, 빈도만으로 스스로 단어를 발견한 것입니다.

## 3. 왜 256개 바이트에서 시작하는가?

### UTF-8과의 관계

전 세계 모든 문자는 **UTF-8** 인코딩으로 0~255 사이의 바이트 조합으로 표현됩니다.

```
글자      코드 포인트    UTF-8 바이트
'A'       U+0041        [65]              ← 1바이트
'é'       U+00E9        [195, 169]        ← 2바이트
'한'      U+D55C        [237, 149, 156]   ← 3바이트
'𝄞'       U+1D11E       [240, 157, 132, 158] ← 4바이트
```

어떤 문자든, 어떤 언어든, 결국 0~255 사이의 숫자로 표현됩니다.

### 왜 이것이 중요한가?

단어 단위 토크나이저에서는 학습 데이터에 없는 단어가 [UNK]가 되었습니다.

BPE는 0~255 바이트에서 시작하기 때문에, **어떤 텍스트도 반드시 표현할 수 있습니다**.

```
단어 단위: "ChatGPT" → [UNK]  (학습 데이터에 없으면 못 읽음)

BPE:       "ChatGPT" → [C][h][a][t][G][P][T]
           → 바이트로 분해하면 반드시 표현 가능
           → 학습 후에는 자주 나오는 패턴은 묶어서 더 짧게 표현됨
```

**OOV 문제가 구조적으로 불가능합니다.** 이것이 BPE가 강력한 가장 큰 이유입니다.

## 4. vocab_size를 키우면 무슨 일이 생기는가?

vocab_size는 "몇 번의 병합을 할 것인가"를 결정합니다.

```
vocab_size = 256    → 병합 0회  (순수 바이트, 글자 단위와 동일)
vocab_size = 300    → 병합 44회 (짧은 패턴들이 합쳐지기 시작)
vocab_size = 1000   → 병합 744회 (흔한 단어들이 단일 토큰이 됨)
vocab_size = 50257  → 병합 49,001회 (GPT-2가 사용하는 크기)
```

### vocab_size에 따른 토큰 수 변화

같은 문장을 vocab_size가 다른 BPE로 인코딩하면:

```
문장: "the quick brown fox"

vocab_size=256  → [116, 104, 101, 32, 113, 117, 105, 99, 107, ...]  (19개 토큰)
vocab_size=300  → [116, 104, 101, 32, 113, ...]                      (약 15개 토큰)
vocab_size=1000 → ['the', 'quick', 'brown', 'fox']                   (약 4개 토큰)
vocab_size=50257→ ['the', ' quick', ' brown', ' fox']                 (4개 토큰)
```

vocab_size가 클수록 토큰 수가 줄어들고, 모델이 처리해야 하는 시퀀스 길이도 짧아집니다.

### 트레이드오프 (Trade-off)

```
vocab_size를 크게 하면:
  장점: 토큰 수 감소 → 처리 속도 향상
  단점: 임베딩 행렬이 커짐 → 메모리 사용량 증가

vocab_size를 작게 하면:
  장점: 임베딩 행렬이 작음 → 메모리 절약
  단점: 토큰 수 증가 → 처리 속도 저하

GPT-2의 선택: 50,257  (균형점)
GPT-4의 선택: 100,277 (더 큰 어휘집으로 더 효율적인 인코딩)
```

## 5. 글자 / 단어 / BPE 최종 비교표

| 비교 항목 | 글자 단위 | 단어 단위 | BPE |
|---|---|---|---|
| 쪼개는 단위 | 글자 1개 | 공백 기준 단어 | 빈도 기반 병합 |
| 초기 어휘집 | 글자 모음 | 단어 모음 | 0~255 바이트 |
| vocab_size (영어) | ~100개 | ~170,000개 | 조절 가능 (~50,000) |
| OOV 문제 | 드묾 | 심각함 | 없음 (구조적 불가) |
| 시퀀스 길이 | 매우 김 | 짧음 | 중간 |
| 의미 단위 보존 | 불가 | 완벽 | 부분적 |
| 다국어 지원 | 언어마다 다름 | 어려움 | 완벽 (UTF-8 기반) |
| 실무 사용 | 거의 없음 | 거의 없음 | 표준 |

## 6. minbpe와 tiktoken(GPT-4)의 관계

### minbpe란?

**minbpe**는 AI 연구자 Andrej Karpathy가 교육 목적으로 만든 BPE 구현체입니다.
GPT를 처음부터 구현하며 가르치는 "makemore", "nanoGPT" 시리즈의 연장선입니다.

```
GitHub: https://github.com/karpathy/minbpe

특징:
  - BPE의 핵심만 깔끔하게 구현
  - BasicTokenizer: 순수 BPE (단어 경계 무시)
  - RegexTokenizer: GPT-4 tiktoken과 동일한 방식
  - 교육용이므로 코드가 짧고 이해하기 쉬움
```

### tiktoken이란?

**tiktoken**은 OpenAI가 GPT-2, GPT-3, GPT-4에 실제로 사용하는 토크나이저입니다.

```
pip install tiktoken

# GPT-4 토크나이저 사용 예시
import tiktoken
enc = tiktoken.encoding_for_model("gpt-4")
tokens = enc.encode("Hello, world!")
# → [9906, 11, 1917, 0]  (4개 토큰)
```

### 두 가지의 관계

```
tiktoken (OpenAI, 실무용)
    ↑ 동일한 원리
minbpe (Karpathy, 교육용)
    ↑ 단순화하여 학습
BasicTokenizer (이 프로젝트)
```

tiktoken과 minbpe의 RegexTokenizer는 다음 핵심을 공유합니다.

1. UTF-8 바이트에서 시작
2. 빈도 기반 병합 반복
3. 정규식으로 단어 경계를 먼저 분리 (RegexTokenizer)

차이점은 tiktoken이 더 빠른 C 구현을 사용하고, 사전 학습된 병합 규칙을 제공한다는 것입니다.

## 7. BPE 학습 데이터가 중요한 이유

BPE의 병합 규칙은 **학습 데이터에 따라 달라집니다**.

```
한국어 텍스트로 학습한 BPE:
  자주 병합되는 쌍: '이다', '하다', '에서', '으로', '을', '를' ...
  → 한국어 형태소가 자연스럽게 토큰이 됨

영어 텍스트로 학습한 BPE:
  자주 병합되는 쌍: 'th', 'he', 'in', 'er', 'an', 'ion' ...
  → 영어 접두사/접미사가 자연스럽게 토큰이 됨

다국어 텍스트로 학습한 BPE (GPT-4 방식):
  두 언어의 패턴이 모두 반영됨
  → 어떤 언어든 효율적으로 인코딩
```

GPT-2는 영어 위주 데이터로 학습되어 한국어를 인코딩하면 토큰 수가 많아집니다.
GPT-4는 더 많은 다국어 데이터로 학습되어 한국어도 효율적으로 처리됩니다.

## 정리

| 개념 | 설명 |
|---|---|
| BPE 핵심 직관 | 자주 붙어 나오는 쌍을 하나의 토큰으로 병합 |
| 초기 어휘집 | 0~255 바이트 (256개 고정) |
| 병합 횟수 | vocab_size - 256 |
| OOV 불가 이유 | 어떤 텍스트도 바이트로 분해 가능 |
| vocab_size 선택 | 속도(짧은 시퀀스)와 메모리(작은 행렬)의 트레이드오프 |
| minbpe | 교육용 BPE 구현체 (Karpathy) |
| tiktoken | OpenAI의 실무 BPE 구현체 (GPT-2/4에 사용) |
